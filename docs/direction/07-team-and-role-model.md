# Team and Role Model

## Purpose

This project currently uses Codex as a force multiplier. The harness must still act like a small game team with explicit disciplines.

## Core Roles

| Role | Owns | Must Not Own |
|---|---|---|
| Game Director | thesis, pillars, final reducer decisions | task-level implementation detail |
| Producer | milestone scope, schedule, cut/defer/keep | creative authority by default |
| Systems Designer | Dream Law, Cover Test, Exposure semantics | NPC prose style |
| Narrative Designer | beats, text surfaces, NPC/Station voice | verdict authority |
| Godot Engineer | scene/runtime presentation, input, UI, evidence scripts | backend rule truth |
| Backend Runtime Engineer | schema, validation, Evidence, fallback | visual staging |
| UX/QA | playability, comprehension, accessibility, regression | rewriting thesis |
| Art/Audio Direction | visual/audio grammar for authority and pressure | adding content without system meaning |

## Codex Role Mapping

Use Codex/subagents as role simulators:
- Director Council lanes for review.
- workers for scoped implementation.
- verifier for evidence.
- contrarian for drift detection.

Do not let a single Codex session act as:
- designer,
- implementer,
- reviewer,
- final director

for the same high-impact decision without explicit review separation.

## Team Recruiting Signal

A skilled collaborator should be able to read the Direction Pack and answer:
- what game this is.
- what it is not.
- what the first playable proof must show.
- where their discipline contributes.
- what evidence counts as done.

If they cannot, the docs are not ready for team recruiting.
