# Week Plan - Prototype v0.1 (2026-02-05)

## Objectives
- Produce a stable, playable MCSS session with deterministic DreamLaw → CoverTest → Inquest loop.
- Ensure UI always explains “why” (law + detector + witness + artifact).
- Validate local LLM flow (Ollama) without violating deterministic boundaries.
- Keep Diagnostics clean and PlayMode tests passing.

## Deliverables (end of week)
- Systems: DreamLaw runtime, detectors, Suspicion/Exposure, CoverTest runtime, Inquest dossier verdict.
- Content: 4 landmarks wired to text surfaces, 6 Cover Tests in data, minimum 3 artifacts per session.
- UI: HUD (suspicion/exposure/cover/checklist), artifact inventory, dossier view.
- QA: Diagnostics clean, PlayMode tests for session start/end, cover test escalation, inquest verdict, LLM off path.

## Workstreams
- **Systems**: DreamLaw + detectors, escalation ladder, verdict scoring.
- **Content**: Text surfaces + CoverTest data across 4 landmarks + global pressure.
- **UI**: Reason visibility, artifact inspection, dossier readability.
- **QA**: Tests + diagnostics + local LLM sanity check.

## Definition of Done (v0.1 week)
- 10–12 min session meets MCSS acceptance.
- No console errors after diagnostics.
- LLM disabled mode works end-to-end.

## Risks / Watchlist
- Missing deterministic linkage between law → evidence → verdict.
- UI fails to show “why” consistently.
- Local LLM integration drifting from endpoint mode.
